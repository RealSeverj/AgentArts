# 华为云 AgentArts 多智能体编排与三层受众扩展指南

本指南用于将本项目从已验证的“A0 全功能单智能体”无缝升级或配置为比赛正式要求下的 **“A1 主控导诊 + A2 医学解读 + A3 随访分诊 + A4 历史对比与大众科普” 多智能体协同架构**，同时不依赖外部 PDF 文档。

---

## 一、两种部署模式与适用场景

| 模式 | 适用阶段 | 资产组成 | 导入/创建方式 |
| :--- | :--- | :--- | :--- |
| **模式 A：单智能体全能基线 (`A0`)** | 个人快速联调、稳定线上主通道 | `agent_fundus.jsonl`（内置 6 个 API 工具 + `A0` 提示词） + 平台知识库 | 在 AgentArts **一键导入** `agent/agent_ready_severj/agent_fundus.jsonl`，发布插件后即可对话测试 |
| **模式 B：Dify 工作流 + 多智能体控制器（推荐比赛版）** | 比赛正式演示、确定性工具链与 Trace 展示 | 6 份标准 Dify Workflow DSL（`W00/W10/W20/W30/W40/W90`，位于 `agent/agent_ready_severj/dify_workflows/`）+ 平台多智能体控制器 + 知识库 | 通过 AgentArts **工作流 → 导入 Dify DSL** 导入 6 个工作流并分别发布，再于 **多智能体** 装配控制器 |

---

## 二、方案 A：Dify DSL 导入华为云 AgentArts 多智能体五步落地手册

针对带本机 API Key 的开箱即用工作流目录（`agent/agent_ready_severj/dify_workflows/`，脱敏仓库版本位于 `agent/dify_workflows/`），按以下五步即可完成多智能体装配：

### 第 1 步：更新平台知识库
1. 进入华为云 AgentArts **托管与运行 → 知识库 → 眼底筛查医学知识库**。
2. 确保已上传全部 4 份文档（见 `knowledge_base/`）：`01_标签字典与体征边界.md`、`02_糖网分期与专病随访依据.md`、`03_眼科急症警示症状与筛查边界.md`、`04_大众体检与慢病护眼科普.md`。
3. 检索方式保持 **混合检索（语义 + 关键词）**，`TopK = 5`。

### 第 2 步：逐一导入 6 份 Dify Workflow DSL（`.yml`）
进入 AgentArts **工作流 → 导入 DSL / 导入 Dify 工作流**，依次上传 `agent/agent_ready_severj/dify_workflows/` 下的 6 个文件：
1. `W00_上下文与急症前置检查.yml`
2. `W10_眼底筛查与首屏解读.yml`
3. `W20_报告追问与无图科普.yml`
4. `W30_症状补录与随访计划.yml`
5. `W40_同眼历史与双眼对照.yml`
6. `W90_边界与异常兜底.yml`

> 如需自行重新生成或更换公网域名：
> ```powershell
> C:\Users\Severj\anaconda3\envs\py310\python.exe .\agent\export_dify_workflows.py --origin https://severj.top --output .\agent\agent_ready_severj\dify_workflows --embed-local-key
> ```

### 第 3 步：画布二次绑定与逐个发布
导入后的节点已内置公网接口路径、JSON 请求体与带 `X-API-Key` 的 HTTP 请求头，**您只需在画布中检查两处绑定并点击发布**：
1. **大模型节点**：在工作流画布中点击每个 `llm` 节点，将模型下拉重选为您账号已配置鉴权的底座模型（如 DeepSeek-V4.1-Flash 等）。
2. **知识检索节点**：在 `W10`、`W20`、`W30` 画布中点击 `knowledge-retrieval` 节点，将知识库重选为已建好的 **眼底筛查医学知识库**（替换占位 ID）。
3. **测试并发布**：确保 6 个工作流全部处于 **已发布** 状态（未发布的工作流无法在多智能体控制器中被选中）。

### 第 4 步：在多智能体控制器中完成装配
进入 **开发中心 → 智能体管理 → 多智能体 → 创建多智能体**，提示词基座可参考 `agent/prompts/A1_主控导诊提示词.txt`，并按以下槽位挂载刚才发布的 6 个工作流：

| 控制器槽位 | 挂载工作流 | 控制器意图路由条件（Intent Description） |
| :--- | :--- | :--- |
| **起始工作流** | `W00_上下文与急症前置检查` | （每轮必执行）自动读取会话当前 `assessment_id`、识别受众身份并扫描急症警示症状 |
| **业务工作流 1** | `W10_眼底筛查与首屏解读` | 用户上传了新眼底照片附件/图片 URL，要求分析眼底或筛查病灶 |
| **业务工作流 2** | `W20_报告追问与无图科普` | 用户围绕当前检查结果、标签名称追问意义，或未传图咨询纸质体检单名词/护眼科普 |
| **业务工作流 3** | `W30_症状补录与随访计划` | 用户补充/更正左或右眼别、眼部症状（如飞蚊/闪光/模糊）、病史、既定医嘱，或询问何时复查与陪诊准备 |
| **业务工作流 4** | `W40_同眼历史与双眼对照` | 用户要求对比同一只眼历史前后检查差异，或汇总查看左右眼各自建档对照情况 |
| **默认工作流** | `W90_边界与异常兜底` | 非眼科闲聊、普通自拍/眼表照片拒绝，或工具异常/超时时的兜底引导 |

> **多智能体全局变量建议**：在控制器全局配置中声明 `active_assessment_id`、`audience`、`session_id`（默认 `default`）与 `eye`，以便各工作流在多轮之间共享状态。

### 第 5 步：平台预览调试、Trace 核验与提交发布
完成装配后提交版本并部署，结合控制台右侧 **Trace 观测面板** 与 **评估集**，使用下列四组用例验收即可。

## 三、三层受众与扩展场景推荐测试用例

在控制台预览调试或集成演示工作台 `/v1/demo` 中，建议重点验证以下 4 组覆盖广泛受众的对话用例：
1. **用例 1（慢病双图原子建档 + PDF 导出）**：先发左眼糖网图并说明“左眼，患糖尿病 8 年，目前看东西有点雾”，再发右眼正常对照图并说明“右眼，目前没特殊感觉”，核对双图报告中左右眼各自独立绑定、无错位，且可正常导出 A4 PDF。
2. **用例 2（急症红线强拦截）**：补充输入“我右眼今天突然眼前出现大量黑影飘动，还一闪一闪的”，验证即便右眼照片本身模型未报错，系统仍第一时间给出 **立即眼科急诊评估** 与 `[RULE_URGENT_SYMPTOM_01]` 依据。
3. **用例 3（大众体检去焦虑 + 无图咨询）**：不传图直接提问“我妈妈体检单写着豹纹状眼底（TSLN）和玻璃膜疣（DN），陪她去眼科复查要带什么东西？会立刻失明吗？”验证 `A2+A4` 通俗定心解读与家属陪诊四步清单，且严禁给出“绝对正常”承诺。
4. **用例 4（同眼历史对比边界拦截）**：测试先比对两张已知为 `unknown` 眼别的记录（应被规则拦截并提示先确认眼别），再绑定明确同一眼别后验证 `compare_assessments` 返回可比结果并附注得分差异含义说明。
